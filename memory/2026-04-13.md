- Storybook coverage for the ranking was expanded to `default`, `overflow`, `productivity`, `loading`, and `empty`, and the smoke/visual Playwright suites were updated to gate those states in light and dark.
- Analytics family sync governance was extended so `RankingModeToggle.tsx`, `TechnicianRankingStrip.tsx`, and `TechnicianRankingStrip.stories.tsx` are exact-match shared files across DTIC, Manutencao, and Conservacao.
- `sync-analytics-family.ps1` had a tooling defect when formatting `package.json` through Node because piped JSON could arrive with UTF-8 BOM; `analytics-family.common.ps1` now strips BOM before `JSON.parse`.
- Family validation passed end to end with `validate-analytics-family.ps1 -IncludeDocker`, including lint, typecheck, build, Storybook smoke, Storybook visual, Docker rebuild, and runtime smoke on `3000`, `3001`, and `3002`.
- The main regression caught from the runtime screenshot was overflow in the new ranking cards: the footer copy (`TICKETS ABERTOS` and relative percent) was rendering below the card boundary. The fix was to simplify the card anatomy, keep a strict `h-[120px]` card with `overflow-hidden`, and remove the repeated metric label from each card.
- A later family rerun failed only because `dashboard-sis-manutencao` had stale visual baselines after a parallel `storybook:visual:update` caused a `6006` Storybook port collision. Rerunning the maintenance visual update sequentially regenerated the snapshots cleanly, and the full family validation passed again with Docker rebuild and runtime smoke.
- The next ranking cleanup removed the relative percentages entirely because they added noise without real semantic value in the horizontal strip. The cards now show only rank, technician identity, primary value, and the comparison bar. The strip header also moved from the mechanical `tecnico(s)` phrasing to a singular/plural copy helper.
- A later refinement fixed the spacing defect between technician identity and primary value in the ranking cards. The incorrect version had the number visually detached in the bottom of the card; the corrected version binds value and comparison bar into the same footer row and uses a mid-height card (`h-[104px]`) so the strip stays compact without clipping the metric.
- Analytics dashboards do not use push or websocket updates; they use SWR polling against `/api/dashboard/snapshot` with `Cache-Control: no-store` and `dynamic = "force-dynamic"`. The family shell now standardizes `refreshInterval: 30_000`, `revalidateOnFocus: true`, and `revalidateOnReconnect: true` in `DashboardShell.tsx`, so DTIC, Manutencao, and Conservacao keep refreshing without manual page reload and immediately revalidate when the user returns to the tab or the network reconnects.
- The hub dashboard chrome was compacted after content review: the top header no longer spends height on generic subtitle and duplicated operator/count copy, and the queue panel no longer repeats `Fila ativa` plus explanatory helper text before the kanban. The board now enters more directly into operation.
- The kanban anatomy was also rebalanced: `Resolvidos` no longer inherits the same visual weight as active states. `KanbanBoard` now assigns narrower column widths to the resolved lane and renders its cards in a compact variant, while `Em atendimento` gets the widest lane. Storybook baselines for `DashboardOverviewHeader` and `DashboardQueuePanel` were regenerated and the hub runtime validation passed after rebuild.
- A runtime-authenticated review exposed a count bug in `DTIC/dashboard`: the header jumped from `294` to `13094` because the page tried to derive "chamados monitorados" from `/db/tickets.total`, but the pilot contract for the surface is `fila ativa + resolvidos em 30 dias`, not the historical total of the SQL list endpoint. The fix was to stop trusting list totals for the dashboard header, derive the header from `stats.totalOpen + stats.solvedRecent`, and scope the resolved lane to recent solved tickets only.
