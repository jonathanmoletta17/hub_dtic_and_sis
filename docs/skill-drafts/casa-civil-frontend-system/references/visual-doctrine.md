# Visual Doctrine

## Purpose

This frontend system exists to keep Casa Civil apps visually coherent without flattening each product into the same template.

## Core Principles

### Preserve product anatomy

Theme work must preserve:

- information hierarchy
- operational density
- shell stability
- CTA cluster stability
- fast scanning of KPIs, tickets, statuses, and actions

### Dark baseline, light parity

- Dark mode is the protected baseline when it already exists.
- Light mode must achieve parity, not just “visibility”.
- Parity means readability, operational feel, and interaction quality.

### Corporate consistency without cloning

Shared consistency should come from:

- typography rhythm
- semantic surfaces
- status colors
- spacing logic
- border and shadow discipline
- accessibility discipline

Not from copying every shell literally between products.

### Operational, not decorative

These applications are work surfaces.

Avoid:

- washed-out pastel dashboards
- generic admin light themes
- ornamental gradients replacing hierarchy
- excessive motion

## Theme Rules

### Surfaces

Separate clearly:

- canvas
- panel
- card
- muted-surface
- floating-surface

### Text

Use strong semantic roles:

- primary
- secondary
- muted
- inverse
- status text

Do not rely on arbitrary opacity for hierarchy.

### Shadows

- Light mode needs lighter, cleaner elevation.
- Dark mode needs deeper, softer elevation.
- Never reuse dark shadows unchanged in light mode.

### Status

Status semantics must survive both themes:

- new
- active
- pending
- solved
- closed

Badges must remain legible and semantically obvious.

### Focus

All critical controls need visible focus in both themes.

### Contrast

If the surface feels washed out, the job is not done even if contrast technically passes.
